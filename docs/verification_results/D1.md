### Findings

**F-01. Siena seizure count (fixed).** The first full run counted 41 Siena seizures, against 47 in the dataset documentation. All 47 were in the seizure lists, but 6 were dropped when each seizure was matched to its recording, because of typos in the file names written in the lists: `PN01.edf` for `PN01-1.edf` (2 seizures), `PNO6-1/2/4.edf` with a letter O for `PN06-1/2/4.edf` (3 seizures), and `PN11-.edf` for `PN11-1.edf` (1 seizure). The matching was fixed in commit `fafad7e`, and the audit report now lists every name it corrected. After the fix, two identical runs gave 47 seizures. The raw data did not change (same checksums). This was a bug in the test script, not a change to the plan's criteria, so it is not a plan deviation.

**F-02. CHB-MIT subjects.** chb01 and chb21 are the same person, recorded about 1.5 years apart. They will be grouped as one patient in cross-patient splits (checked in VT-08), so CHB-MIT contributes at most 23 test patients.

**F-03. Mental arithmetic is too short for FAR.** The set totals 2.4 h, about 2 min per recording. At the D2 target of 5 false alarms per 24 h, only about 0.5 false alarms would be expected in 2.4 h, so this set can't estimate a false alarm rate. It is still useful for checking that task-related EEG changes don't trigger alarms. The main false-alarm set is the TUSZ patients without seizures (D-5).

**F-04. Notes for the loader (VT-05).** The Siena seizure lists mix time formats (`21:51:02`, `16:13.23`), some seizures happen after midnight in recordings that started the evening before, and PN10 seizure 3 lists both a clinical onset (15.43.53) and an electrographic onset (15.43.59). I'll use the electrographic onset, since the model only sees EEG.

**F-05. Still to check.** The TUSZ seizure count (2,664, from the `.csv_bi` files) hasn't been compared with NEDC's official numbers yet. TUSZ patients who appear in more than one official split, and TUAR patients who are also in TUSZ, are listed in `results/d1/data_audit.md` and `results/d1/tuar_tusz_overlap.csv`.

## VT-02 to VT-05 Harmonization

Run on 2026-09-25 with `scripts/check_harmonization.py` at commit `8f84b18`, Python 3.13.2, M4 MacBook. The script runs the unit tests (82 passed) and then checks all 9,249 recordings. The full run, including reading and resampling all 158 GB for VT-03, took about 3.5 minutes. The full report is `results/d1/harmonization_check.md`.

### VT-02 Channel name mapping: PASS

The unit tests cover every label format found in the data: TUH labels (`EEG T3-REF`, `EEG T3-LE`), Siena's mixed spellings (`EEG FP2` and `EEG Fp2`), CHB-MIT bipolar pairs, CHB-MIT's referential files (including `01` written for O1 and channels referenced to `CS2`), and non-EEG, numbered and empty placeholder channels.

On the corpus, every channel in all 9,249 recordings was either used or excluded with a reason, and no EEG channel was left unmapped (`results/d1/channel_log.csv`). Most recordings have all 18 derivations. TUSZ recordings without Fz and Pz electrodes have 16, with Fz-Cz and Cz-Pz marked absent (`results/d1/derivation_availability.csv`).

### VT-03 Resampling and units: PASS

Unit tests: 10 Hz sine waves at 250, 400, 500 and 512 Hz resampled to 256 Hz keep their frequency within 0.1 Hz and amplitude within 1%, and have the expected length. mV and V files are converted to µV.

Corpus: 98.5% of derivations have a median absolute amplitude between 1 and 200 µV (criterion: at least 95%), and every harmonized recording has length duration × 256 ± 1 sample. The remaining 1.5% are listed in `results/d1/amplitude_check.csv` (see F-12).

### VT-04 Montage conversion: PASS

Unit tests: every derivation equals the difference of its two electrodes to within 1e-6 µV; the output is the same whether the input is referenced to the average, to linked ears, or not re-referenced; a derivation with a missing electrode is marked absent, not filled; bipolar pairs stored in reverse are negated; and electrodes with different references are never combined.

### VT-05 Annotation preservation: PASS after corrections

The first run failed on 2 of 2,909 seizures, both errors in the datasets' own annotations (F-06, F-07). They were handled through `configs/annotation_corrections.yaml`, which lists each correction with its evidence; the raw files are unchanged. After that, all 2,908 remaining seizures (CHB-MIT 198, Siena 47, TUSZ 2,663) fall inside their recordings, to within ±1 sample at 256 Hz. The loader's counts match VT-01 once the one excluded seizure is counted.

Visual review: 10 seizures chosen at random with seed 0 (3 CHB-MIT, 3 Siena, 4 TUSZ). Every onset marker falls at, or up to about 15 s before, a visible change in the EEG, and none is misplaced. I also reviewed the 4 seizures the loader flagged (F-06, F-08). Figures are in `results/d1/figures/`.

### Findings

**F-06. Siena PN00-3 end time (corrected).** The seizure list gives the end as 19.29.29, which is after the list's own registration end (18.57.13) and would make the seizure 61 min long. I assumed an hour typo for 18.29.29 (825 s into the recording) and corrected it in `configs/annotation_corrections.yaml`. The EEG confirms this: the rhythmic right temporal discharge stops at 825 s (`flagged_01_siena_PN00-3_used.png`).

**F-07. TUSZ aaaaapks_s016_t000 zero-length row (excluded).** The `.csv_bi` file has a seizure row from 0.0 to 0.0 s, followed by seven normal seizure rows. It is excluded. This doesn't change any labels, since the start of that file is within 4 h of the other seizures. The same patient's recording aaaaapks_s002_t010 starts mid-seizure, so the zero-length row probably marks a seizure continuing from an earlier file.

**F-08. Siena start-time conflicts.** In three seizure lists, the "registration start time" disagrees with the EDF header. The loader uses the header time and plots both timings for review.

| Entry | List | EDF header | Result |
|---|---|---|---|
| PN10 entry 7 | 06:49:25 | 16:49:25 | Header confirmed: clear onset at the red line; the list's time would put the seizure outside the recording |
| PN14 entry 3 | 16:17:45 | 19:17:45 | Header confirmed: seizure builds from the header onset; ordinary background at the list's time |
| PN05 entry 2 | 06:01:23 | 06:01:13 | Can't tell apart: both are within about 10 s of a large burst at about 6839 s. Header kept for consistency; the 10 s difference is within normal onset variability |

**F-09. Onset variability.** Some annotated onsets come up to about 15 s before the clearest visible change (Siena PN00-3, PN06-5). That is normal variation in where annotators mark onsets, and small compared with the 30 min preictal window, but it adds a few seconds of uncertainty around the 5 s prediction horizon. Onsets are used as annotated, as the plan specifies.

**F-10. Recordings that start mid-seizure.** Some TUSZ recordings begin during a seizure (e.g. aaaaapks_s002_t010, onset at 1 s). They have no preictal data and are handled by the eligible-seizure rule (at least 90% of the preictal window recorded).

**F-11. Requirement for the labeling step (VT-06).** An excluded seizure must still block its surroundings: the time around it can't be labeled interictal, or preictal EEG would be labeled as normal. The loader keeps excluded seizures in a separate list for this.

**F-12. Amplitude outliers.** 1.5% of derivations have a median amplitude outside 1-200 µV. This passes VT-03, but before training I'll look at `results/d1/amplitude_check.csv` to see whether they are flat (disconnected electrodes) or dominated by artifact, and whether they should be marked absent.

## VT-06 and VT-07 Labels

Run on 2026-09-25 with `scripts/build_labels.py` at commit `1dfefa7`, windows of 30 s every 5 s. The first run, at commit `9d8c85e`, also passed both tests but mishandled TUSZ timing (F-14), so the report was regenerated after the fix. The full report is `results/d1/label_report.md`.

### VT-06 Labeling rules: PASS

33 unit tests on synthetic timelines, covering:

* every label boundary to within 0.01 s (4 h before onset, 30 min before, 5 s before, onset, offset, and 4 h after);
* seizures less than 30 min apart merging into one event;
* the 90% coverage rule, with seizures just above and just below it;
* a preictal period continuing into the previous file;
* recordings crossing midnight;
* small and impossible overlaps between files;
* TUSZ rules (D-5): seizure-free sessions, files without usable start times, and patients with no seizures;
* excluded seizures still blocking interictal labels (F-11);
* chb21 kept as its own timeline but the same subject as chb01;
* windows at several lengths labeled by their end time.

### Findings

**F-13. TUSZ has no usable preictal data.** Every TUSZ header gives the start as 00:00:00 on 1 January of the recording year, so the start times are anonymized. TUSZ files are at most 30 min long (median 10 min), and the latest seizure starts 22 min into its file. Without real start times, a session's files can't be joined, so the best any TUSZ seizure gets is 74% of its 30 min lead-up recorded, below the 90% rule. None of the 1,097 TUSZ events is eligible and no TUSZ patient can be a test patient. TUSZ was built for seizure detection, where this doesn't matter. In this project it provides interictal EEG and a large false-alarm test set instead (see F-17).

**F-14. Anonymized start times first taken as real (fixed).** The first label run treated the 00:00:00 start times as real and placed every file of a TUSZ session at the same moment, which produced 6,499 overlap warnings. No wrong labels resulted, since no TUSZ event was eligible and all time in seizure sessions fell within 4 h of a seizure. But that outcome was luck, not design. Since commit `1dfefa7`, when every file in a group reports the same start time, the times are treated as unknown and each file is labeled on its own, with no interictal time if its session has a seizure (D-5). This affected 1,031 TUSZ sessions (7,528 files). Because files are no longer stacked, seizures in different files are no longer merged, which is why TUSZ events went from 427 to 1,097.

**F-15. Two CHB-MIT files with impossible start times.** chb10_89 and chb18_36 would start 670 s and 3,369 s before the previous file ends, which can't happen in continuous monitoring, so their position is unknown. Each is labeled on its own. CHB-MIT still has 122 eligible events; preictal time went from 60.8 h to 60.6 h.

**F-16. Few Siena test patients.** 40 of Siena's 47 seizures are eligible, but only 4 of 14 patients have at least 1 h of interictal EEG, because Siena recordings are fairly short and dense with seizures. The other 10 patients are used for training only.

**F-17. TUSZ is not used for D1 training.** Because TUSZ could only add interictal examples (about 64% of all interictal time) from a different hospital and different equipment, a model could learn to recognize TUSZ recordings instead of the changes before a seizure. D1 trains on CHB-MIT and Siena, where every training patient contributes both preictal and interictal EEG, and uses TUSZ for false-alarm testing. Adding TUSZ interictal EEG to training is a pre-planned D2 experiment. The reasoning and the rest of the evaluation setup are in `docs/evaluation_methods.md`, written before any model was trained.
